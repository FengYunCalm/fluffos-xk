# 回滚与恢复运行手册

> 适用：自用部署出现运行时崩溃、性能异常或安全事件，需要回退 driver
> 或下游配置时。默认使用经过测试的 commit 和本地构建产物，不依赖公开
> Release、registry 或官方发布流程。

## 1. 判断是否需要回滚

| 症状 | 处置 |
| --- | --- |
| 新构建启动即崩溃/段错误 | 立即回到上一已验证 commit 的构建 |
| 新构建 CPU/内存异常增长 | 保留现场（日志/核心转储）后回退 |
| gateway 错误、queue reject、timeout 超阈值 | 停止压力，保留现场，回退 |
| owner claim/future/object ref 持续增长 | 停止长时运行，保留现场，回退 |
| 安全事件（漏洞利用/泄露） | 按 `gateway-security.md` 处理，必要时离线 |

## 2. 回滚步骤

1. **保留现场**：复制 `debug.log`、core dump、`build/reports/`、进程 `ps`
   快照到安全目录，注明 commit 与运行配置；不删除日志。
2. **切换构建产物**：将下游运行树中的 `driver`、`lpcc` 或容器镜像换回上一
   个经过验证的本地构建。需要重建时，检出对应 commit 并使用匹配的
   `CMakePresets.json` preset。
3. **验证回退**：确认服务健康检查通过、无新错误增量、版本号和运行配置正确，
   再恢复正常流量。
4. **记录**：在下游事故记录中写时间、触发 commit、回退目标、恢复时长、
   受影响 mudlib 和兼容性影响。

## 3. 不需要回滚的情况

- 文档或证据漂移：不触发二进制回滚，直接修正文档并重新运行相关检查。
- 尚未部署到下游的构建失败：保留失败日志，修复后重新构建。
- 仅有非兼容性文档改动：不影响已部署 driver。

## 4. 客户端和 mudlib 兼容

- 若协议、efun 或配置字段有破坏性变更，回退时同时回退下游客户端配置和
  mudlib 适配；在 `CHANGELOG.md` 与相关技术文档记录影响面。
- 若只回退 driver，先确认下游 mudlib 没有依赖新版本的持久化格式或新增 API。
- 回退完成后运行受影响的 C++、LPC、sanitizer 和下游 smoke 检查；检查失败时
  保留现场，不宣称恢复完成。
